System Architecture

CareerCoach AI Backend

A Flask-based monolithic web application that delivers AI-powered career coaching — resume analysis, interview prep, salary guidance, and more — backed by Amazon Bedrock (Claude) and SQLite.

High-Level Overview

The backend follows a classic three-tier monolith pattern: a browser client interacts with Flask routes that render Jinja2 templates or return JSON; business logic lives in Python modules; persistence uses SQLite; and AI workloads are delegated to AWS Bedrock via HTTP.

Core Modules

app.py
Central Flask application (~876 lines). Defines all HTTP routes, session-based auth, SQLite schema initialization, password hashing (Werkzeug + legacy SHA-256 migration), profile management, and orchestrates calls to AI, guardrails, and utilities.
ai_service.py
AI integration layer. Calls Amazon Bedrock Converse API (Claude Haiku by default) via requests. Exposes feature-specific functions: chat, resume analysis, job matching, cover letters, LinkedIn summaries, salary advice, and interviews.
guardrails.py
Safety and content policy layer. Validates user input length and blocked keywords, builds personalized system prompts from user profile, sanitizes AI output (XSS/injection blocklist), and enforces career-only topic scope.
security.py
Cross-cutting security: Flask-WTF CSRF protection, in-memory sliding-window rate limiter for AI endpoints (default 20 req/min), and PDF upload validation (magic bytes, 10 MB cap).

Request Flow (Authenticated AI Feature)

1. Browser POST (JSON + CSRF token) → 2. require_login() — session check → 3. enforce_ai_rate_limit() → 4. validate_message() / read_validated_pdf() → 5. ai_service.*() → 6. Bedrock Converse API → 7. sanitize_ai_output() → 8. log_ai_usage() + JSON response

Authentication & Sessions

Auth Model

  • Server-side Flask sessions (cookie-based)
  • Session stores user_id and email
  • Passwords hashed with Werkzeug generate_password_hash
  • Legacy SHA-256 hashes auto-migrated on login
  • CSRF tokens via Flask-WTF on all forms/AJAX
  • Secure cookies in production (SESSION_COOKIE_SECURE)

Auth Routes

  • /signup — JSON registration + auto-login
  • /login — form POST, redirects to onboarding or dashboard
  • /forgot-password — token generation (1 hr expiry)
  • /reset-password/<token> — password reset
  • /logout — clears session
  • /onboarding — first-time profile setup

Frontend Architecture

Server-Rendered (SSR)

  • Jinja2 template inheritance via base.html
  • Tailwind CSS (CDN) + custom app.css
  • Dark mode toggle persisted in localStorage
  • CSRF token injected in meta tag for fetch calls
  • Marked.js for rendering AI markdown in chat

Client-Side (SPA-lite)

  • Feature pages use fetch() POST for AI actions
  • JSON responses update DOM without full page reload
  • Toast notifications via showToast()
  • Resume upload uses multipart form data

Security & Guardrails

Input

  • Max message lengths per field type
  • Blocked keyword filter (jailbreak, off-topic)
  • Email regex validation
  • PDF magic-byte + size validation
  • secure_filename() on uploads

Output

  • XSS blocklist on AI responses
  • Unicode normalization
  • Career-only system prompts
  • JSON field sanitization for structured AI data

Rate Limiting

  • In-memory sliding window per user
  • Default: 20 requests / 60 seconds
  • Tracked in ai_usage table
  • 429 response when exceeded
  • /api/usage exposes remaining quota
